La Metáfora de la Fábrica Inteligente

Piensa en tu app como una fábrica: El Modelo es el plano de la pieza. El UIState es la caja que contiene los productos terminados. El ViewModel es el encargado de la máquina que añade o modifica piezas. Compose (la UI) es el mostrador de la tienda: solo mira la caja y la muestra al cliente. ¡El mostrador nunca fabrica piezas directamente!

3
Paso 3: Construye el ViewModel con StateFlow

Declara el MutableStateFlow privado (con guión bajo) y expón el StateFlow público de lectura. Aplica cambios siempre con _modulosUIState.update { it.copy(...) }.

KOTLIN · ui/ModuloViewModel.kt 
package com.example.ud4_ejercicio.ui

import androidx.lifecycle.ViewModel
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update
import com.example.ud4_ejercicio.modelo.modulo
import com.example.ud4_ejercicio.modelo.ModuloUIState

class ModuloViewModel : ViewModel() {
    // 1. Privado: solo el ViewModel puede mutar el flujo
    private val _modulosUIState = MutableStateFlow(ModuloUIState())

    // 2. Público: la UI solo lee este StateFlow
    val modulosUIState: StateFlow<ModuloUIState> = _modulosUIState.asStateFlow()

    // 3. Modificaciones inmutables mediante copy()
    fun updateModulo(nombre: String, urgente: Boolean, descripcion: String, titulo: String) {
        val nuevo = modulo(nombre, urgente, descripcion, titulo)
        _modulosUIState.update { estadoActual ->
            estadoActual.copy(
                moduloActual = nuevo,
                listaModulo = estadoActual.listaModulo + nuevo // Inmutable: crea una lista nueva
            )
        }
    }
}
4
Paso 4: Construye la Interfaz Composable

Conecta la pantalla con collectAsState(). Mantén los inputs temporales en estados locales con remember { mutableStateOf("") } y al pulsar el botón llama al ViewModel.

KOTLIN · MainActivity.kt (Formulario) 
@Composable
fun Formulario(
    moduloViewModel: ModuloViewModel = viewModel(),
    modifier: Modifier = Modifier
) {
    // Escucha el StateFlow y se recompone automáticamente
    val uiState by moduloViewModel.modulosUIState.collectAsState()

    // Estados locales para los campos de texto
    var titulo by remember { mutableStateOf("") }
    var descripcion by remember { mutableStateOf("") }
    var urgente by remember { mutableStateOf(false) }

    Column(modifier = modifier.padding(16.dp)) {
        OutlinedTextField(
            value = titulo,
            onValueChange = { titulo = it },
            label = { Text("Título") },
            modifier = Modifier.fillMaxWidth()
        )

        Button(
            onClick = {
                moduloViewModel.updateModulo("PMDM", urgente, descripcion, titulo)
                titulo = "" // Limpia el formulario
                descripcion = ""
            },
            modifier = Modifier.fillMaxWidth().padding(top = 12.dp)
        ) {
            Text("Añadir módulo")
        }

        LazyColumn(modifier = Modifier.fillMaxSize().padding(top = 16.dp)) {
            items(uiState.listaModulo, key = { it.id }) { item ->
                Text("${item.nombre}: ${item.titulo}")
            }
        }
    }
}

✅ Las 3 Reglas de Oro de Jetpack Compose

ReglaExplicaciónConsecuencia si no la cumples
1. UDF (Flujo Unidireccional) El estado viaja hacia abajo (ViewModel → UI), los eventos viajan hacia arriba (UI → ViewModel). Código espagueti, estados desincronizados y fallos de recomposición.
2. Inmutabilidad Estricta Nunca hagas lista.add(). Haz lista = lista + nuevoElemento con copy(). Compose no detecta cambios en colecciones mutadas y la pantalla no se actualiza.
3. innerPadding Obligatorio Pasa siempre innerPadding del Scaffold al Composable hijo con Modifier.padding(innerPadding). La barra superior del sistema o el notch taparán la mitad de tu primer componente.

🎨 Laboratorio Visual: Cómo Funciona el Ciclo de Compose

Comprende cómo los datos fluyen en una sola dirección (UDF) y por qué Compose nunca necesita modificar vistas manualmente como en el antiguo XML.

Comparativa: Android Tradicional (XML) vs Jetpack Compose

AspectoAndroid Antiguo (XML + Imperativo)Jetpack Compose (Moderno y Declarativo)
Definición Archivos activity_main.xml separados del código Kotlin. Funciones @Composable escritas 100% en Kotlin.
Búsqueda de Vistas findViewById<TextView>(R.id.miTexto) (propenso a NullPointer). No existe: el Composable se llama directamente con los parámetros.
Actualizar un Texto miTextView.text = "Nuevo" (modificación manual en caliente). Cambias el estado y Compose recompone la función automáticamente.
Listas RecyclerView + Adapter + ViewHolder (60 líneas de código). LazyColumn { items(lista) { ... } } (solo 5 líneas de código).

El Flujo Unidireccional de Datos (UDF)

1. Usuario hace clic en Añadir ➔ 2. Formulario invoca updateModulo() ➔ 3. ViewModel emite nuevo ModuloUIState ➔ 4. collectAsState() detecta el cambio ➔ 5. LazyColumn redibuja la lista
¡Magia de la Recomposición! Compose es lo bastante inteligente como para NO volver a dibujar toda la pantalla: solo redibuja la fila recién añadida en LazyColumn.

📘 Fundamentos de Android, Kotlin y Ciclo de Vida de la Activity

Comprende la estructura de un proyecto Android moderno, el ciclo de vida de una ComponentActivity y cómo se inicializa Jetpack Compose.

El Ciclo de Vida de una Activity

Una ComponentActivity pasa por varios estados a lo largo de su existencia: desde que el usuario pulsa el icono de la app hasta que la destruye o cambia a otra tarea.

MétodoMomento en que se ejecutaUso habitual de examen
onCreate()La Activity se crea en memoria por primera vez.Llamar a enableEdgeToEdge() e iniciar setContent { ... }.
onStart()La Activity se vuelve visible para el usuario.Iniciar componentes que solo deben funcionar en pantalla.
onResume()La Activity tiene el foco y puede recibir toques del usuario.Reanudar animaciones, sensores o cámaras.
onPause()La Activity pierde el foco (ej: aparece un diálogo o llamada).Pausar procesos que consuman batería o CPU.
onStop()La Activity ya no es visible para el usuario.Guardar datos temporales en disco o base de datos.
onDestroy()La Activity se destruye completamente.Liberar recursos y desuscribir observables.
KOTLIN · Ud4_Ejemplo1 · CICLO DE VIDA CON LOGCAT
package com.example.ud4_ejemplo1

import android.os.Bundle
import android.util.Log
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.activity.enableEdgeToEdge
import androidx.compose.material3.Text

private const val TAG = "CicloDeVida"

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        Log.d(TAG, "onCreate() -> Inicializando Compose")
        enableEdgeToEdge()
        setContent {
            Text("¡Hola Mundo en Jetpack Compose!")
        }
    }

    override fun onStart() { super.onStart(); Log.d(TAG, "onStart()") }
    override fun onResume() { super.onResume(); Log.d(TAG, "onResume() -> App lista para interactuar") }
    override fun onPause() { super.onPause(); Log.d(TAG, "onPause()") }
    override fun onStop() { super.onStop(); Log.d(TAG, "onStop()") }
    override fun onDestroy() { super.onDestroy(); Log.d(TAG, "onDestroy()") }
}

¿Qué es el Estado en Compose?

🧠
La Memoria de un Composable

Las funciones @Composable se ejecutan una y otra vez (se recomponen). Si creas una variable normal como var texto = "", cada vez que la pantalla se vuelva a dibujar, esa variable volverá a valer "". Por eso usamos remember { mutableStateOf("") }: le dice a Compose "¡acuérdate de este valor aunque vuelvas a dibujar la función!".

KOTLIN · DECLARACIÓN DE ESTADO LOCAL
// Forma recomendada con delegado 'by' (requiere import androidx.compose.runtime.getValue y setValue)
var textoInput by remember { mutableStateOf("") }
var estaMarcado by remember { mutableStateOf(false) }

// rememberSaveable conserva los datos si el usuario gira el móvil de vertical a horizontal
var textoPersistente by rememberSaveable { mutableStateOf("") }

📋 Listas Eficientes con LazyColumn y Tarjetas Card

Renderiza cientos o miles de elementos de forma ultrarrápida. Uso de items(), recursos tipados (@StringRes y @DrawableRes), y elevación de clics con callbacks.

¿Por qué LazyColumn y no Column?

Column crea y mide todos sus elementos de golpe, aunque no quepan en pantalla. Si tienes 500 elementos, la app se quedará sin memoria (OutOfMemory). En cambio, LazyColumn solo dibuja los elementos que el usuario está viendo en ese momento exacto.

Regla: Para listas de tamaño variable o superior a 5 elementos, usa SIEMPRE LazyColumn.

Modelo Bandera y Lista con Tarjetas

KOTLIN · Ud3_Ejemplo1 · LISTA DE BANDERAS
// 1. Modelo con anotaciones de recursos de Android
data class Bandera(
    @StringRes val nombre: Int,
    @DrawableRes val imagen: Int
)

// 2. Lista de datos de ejemplo
object Datos {
    fun cargarBanderas(): List<Bandera> {
        return listOf(
            Bandera(R.string.espana, R.drawable.espana),
            Bandera(R.string.francia, R.drawable.francia),
            Bandera(R.string.italia, R.drawable.italia)
        )
    }
}

// 3. Composable con LazyColumn
@Composable
fun ListaBanderas(banderas: List<Bandera>, onItemClick: (Bandera) -> Unit) {
    LazyColumn(
        contentPadding = PaddingValues(16.dp),
        verticalArrangement = Arrangement.spacedBy(8.dp)
    ) {
        items(items = banderas, key = { it.nombre }) { bandera ->
            Card(
                modifier = Modifier
                    .fillMaxWidth()
                    .clickable { onItemClick(bandera) },
                elevation = CardDefaults.cardElevation(defaultElevation = 4.dp)
            ) {
                Row(
                    modifier = Modifier.padding(16.dp),
                    verticalAlignment = Alignment.CenterVertically
                ) {
                    Image(
                        painter = painterResource(id = bandera.imagen),
                        contentDescription = stringResource(id = bandera.nombre),
                        modifier = Modifier.size(64.dp)
                    )
                    Spacer(modifier = Modifier.width(16.dp))
                    Text(
                        text = stringResource(id = bandera.nombre),
                        style = MaterialTheme.typography.titleMedium
                    )
                }
            }
        }
    }
}

🧠 Arquitectura MVVM y Flujo Unidireccional con StateFlow

Domina la separación en tres capas: Modelo, Vista y ViewModel. Manejo de StateFlow, MutableStateFlow, asStateFlow(), update { copy() } y collectAsState().

¿Por qué MVVM? El Problema de Sobrevivir a Giros

Si guardas datos importantes dentro de una Activity o Composable, cuando el usuario gira el teléfono móvil o entra en segundo plano, la Activity se destruye y se vuelve a crear. El ViewModel vive fuera del ciclo de vida de la Activity: ¡sus datos no se borran al rotar la pantalla!

ElementoTipoVisibilidadPropósito
_uiStateMutableStateFlow<MiUIState>private valContenedor interno editable solo por el ViewModel.
uiStateStateFlow<MiUIState>val (público)Flujo de solo lectura expuesto con asStateFlow() a Compose.

Caso Práctico: Calculadora Reactiva MVVM (Ud4_Ejemplo2)

KOTLIN · Ud4_Ejemplo2 · OperacionViewModel.kt
package com.example.ud4_ejemplo2.ui

import androidx.lifecycle.ViewModel
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update
import com.example.ud4_ejemplo2.modelo.OperacionUIState

class OperacionViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(OperacionUIState())
    val uiState: StateFlow<OperacionUIState> = _uiState.asStateFlow()

    fun actualizarOperando1(nuevo: String) {
        val n1 = nuevo.toIntOrNull() ?: 0
        _uiState.update { actual ->
            val n2 = actual.operando2.toIntOrNull() ?: 0
            actual.copy(operando1 = nuevo, resultado = n1 + n2)
        }
    }

    fun actualizarOperando2(nuevo: String) {
        val n2 = nuevo.toIntOrNull() ?: 0
        _uiState.update { actual ->
            val n1 = actual.operando1.toIntOrNull() ?: 0
            actual.copy(operando2 = nuevo, resultado = n1 + n2)
        }
    }
}

El AlertDialog en Compose

En Jetpack Compose, los diálogos no se abren con dialog.show(). Simplemente se declaran dentro de un condicional if (mostrarDialogo). Si la variable es verdadera, Compose dibuja el diálogo sobre la pantalla.

KOTLIN · Ud4_Ejemplo3 · DIÁLOGO DE FIN DE JUEGO
@Composable
fun DialogoFinJuego(
    haGanado: Boolean,
    puntuacion: Int,
    onReiniciar: () -> Unit
) {
    AlertDialog(
        onDismissRequest = { /* No cerrar al pulsar fuera */ },
        title = {
            Text(if (haGanado) "🎉 ¡ENHORABUENA!" else "💀 FIN DE LA PARTIDA")
        },
        text = {
            Text("Puntuación acumulada: $puntuacion puntos.\n¿Deseas jugar otra ronda?")
        },
        confirmButton = {
            Button(onClick = onReiniciar) {
                Text("Volver a jugar")
            }
        }
    )
}

Jerarquía de Clases: open class y subclases

KOTLIN · Ud4_Ejercicio4 · MODELOS POO
// 1. Clase base abierta a herencia
open class Producto(
    val nombre: String,
    val precioBase: Double
) {
    open fun calcularPrecio(): Double = precioBase
}

// 2. Subclase Hamburguesa con suplementos
class Hamburguesa(
    nombre: String,
    precioBase: Double,
    val quesoExtra: Boolean,
    val bacon: Boolean
) : Producto(nombre, precioBase) {
    override fun calcularPrecio(): Double {
        var suplemento = 0.0
        if (quesoExtra) suplemento += 1.50
        if (bacon) suplemento += 2.00
        return precioBase + suplemento
    }
}

// 3. Subclase Pizza con selección de tamaño
class Pizza(
    nombre: String,
    precioBase: Double,
    val esFamiliar: Boolean
) : Producto(nombre, precioBase) {
    override fun calcularPrecio(): Double {
        return if (esFamiliar) precioBase * 1.5 else precioBase
    }
}

📖 Glosario Técnico y las 10 Trampas Mortales de Examen

Los errores que más suspensos provocan en los exámenes de 2º DAM de Android y cómo esquivarlos limpiamente.

⚠️ Las 10 Trampas Mortales de Examen

Trampa 1: Olvidar by remember al declarar estados locales (escribir solo val texto = mutableStateOf("")). Resultado: tienes que escribir texto.value en todos lados.
Trampa 2: Mutar una lista directamente (ej: uiState.lista.add(nuevo)). Compose NO detectará el cambio y no redibujará la pantalla. Usa siempre copy(lista = actual.lista + nuevo).
Trampa 3: Olvidar pasar innerPadding de Scaffold al Composable hijo. La barra del sistema tapará el primer elemento.
Trampa 4: No usar el operador Elvis ?: 0.0 tras toDoubleOrNull(). Si el campo está vacío, la app crasheará con NullPointerException.
Trampa 5: Usar singleLine = true en campos de descripción larga impidiendo al usuario ver lo que escribe.
